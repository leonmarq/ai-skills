---
name: pilot
description: Build one variant end to end before the rest. Use when one feature needs several parallel versions that each take their own real work.
---

Variants are parallel versions of one feature, such as PDF, DOCX and CSV export or multiple payment providers. What you learn from the first usually changes how you build the others, so get one working before repeating the work.

1. Pick the variant the user named, or else the one that matters most. Say which in one line.
2. Build it end to end and verify it works.
3. Stop, list the remaining variants, and ask before building them.

Skip this skill when comparing design alternatives, for mechanical repeats of a requested fix, and for anything a project requires for a feature to count as done: translations, supported platforms and parity rules.
